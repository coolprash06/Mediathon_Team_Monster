--------------------------------------------------------------------------------

  allowed. Build in plain/vanilla HTML, CSS, and JavaScript.

  library) is NOT allowed. Must be built in plain/vanilla JavaScript only —
  no rendering libraries, no external dependencies of any kind for the
  interactive scene.

--------------------------------------------------------------------------------
 TEAM MONSTER — SITE CONCEPT NOTES (not official rules, for our own build)
--------------------------------------------------------------------------------
BUILD CONSTRAINT: 100% plain/vanilla HTML, CSS, JS. No Three.js, no other
external JS libraries (confirmed with organizers). "3D" room effect to be
achieved with CSS 3D transforms (perspective, translateZ, rotateX/Y) and
transitions — not WebGL/canvas rendering.

ROOM (retro security-room aesthetic — CRT monitors, olive-green filing
cabinets, wooden desk, brass desk lamp; see reference photos, not copied
directly):
- Dark "security/dilapidated room" scene. Room starts in shadow/outline only.
- Pull-chain lamp interaction turns on the room lighting (reveal/fade via
  CSS class toggle + transition, triggered by JS click on the chain).
- Once lit: 3 desktops + 2 file cabinets (4 drawers each = 8 drawers total)
  are visible and clickable.

DESKTOPS (rush-hour phases, one photo set each):
- Desktop 1 = Morning Rush, Desktop 2 = Afternoon Rush, Desktop 3 = Peak Rush.
- Click a desktop -> camera/view zooms to a front-on view of that screen.
- Below the screen: a button reading "Click to See Pictures from the
  [Morning Rush/Afternoon Rush/Peak Rush]" (per-desktop label).
- Clicking the button starts a one-at-a-time slideshow of that time
  window's photos, regardless of location.
- Slideshow nav: "<-" icon/button bottom-left of screen (previous image),
  "->" icon/button bottom-right of screen (next image).

FILE CABINETS (location-based, drawer -> file -> photos):
- 2 cabinets, 4 drawers each. 6 drawers used for categories, 2 bottom
  drawers (one per cabinet) left empty.
- Drawer labels: Canteen, Outdoor, MTH Mall, Student Lounge, Corridors,
  Sports Complex.
- Click a cabinet -> camera/view zooms toward it.
- Click a drawer -> drawer slides open (CSS transform/transition),
  revealing a file inside labeled with its category name.
- "Take the file" button appears, plus "Put it back" to close the drawer.
- Clicking the file graphic directly (not just the button) ALSO triggers
  the same action — give the file itself a generously-sized clickable
  area, not just the button.
- Taking the file animates it (CSS transform translate) from the drawer
  position to a fixed spot on the desk near the lamp. Lands closed, shows
  "Open the file" button + "Put it back" (returns file to drawer).
- "Open the file" transitions into a spread/slideshow view of that
  category's venue photos, with page-counter style navigation
  (prev/next), matching the desktop slideshow pattern for consistency.
- Some photos may reasonably appear under both a time-of-day desktop AND
  a location drawer (e.g. a lunchtime canteen shot) — shot list should
  tag each photo with both its time and its location.

NAVIGATION:
- An explicit "Back to Room" control is present in every zoomed-in view
  (desktop slideshow, cabinet, open drawer, open file) — lets the visitor
  return directly to the full room view at any point, not just via
  "Put it back"/closing individual elements.
